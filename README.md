# Задачи — первый плагин Shtab

Есть модель, миграции и интерактивный интерфейс списка / Kanban. HTTP API задач пока нет;
`/api/plugins/todo/health` проверяет подключение backend и требует входа.

```text
todo/
├── manifest.json          # описание для загрузчика и интерфейса
├── pyproject.toml         # установка Python-пакета
├── src/shtab_todo/
│   ├── main.py            # register(app), подключает роутер к ядру
│   ├── config.py          # будущие настройки
│   ├── db.py              # фабрика сессий ядра, свои метаданные
│   ├── models.py          # Task и TaskStatus
│   ├── migrations/       # независимая история схемы Todo
│   └── mcp.py             # на потом
└── frontend/              # Web Component, стили и временное хранилище
```

## Как читать манифест

- `id` — постоянный ID; `name` — название в интерфейсе; `version` — версия пакета.
- `url: local:todo` — источник в workspace. Для установки из GitHub передайте в `POST /api/plugins` копию манифеста с URL репозитория в поле `url`.
- `backend_entrypoint` — импортировать `shtab_todo.main` и вызвать `register(app)`.
- `frontend.entry` — JS-файл относительно папки с манифестом.
- `pages` — маршрут браузера и зарегистрированный Web Component.
- `menu_items` — куда ядро добавит ссылку. `sidebar.main` — основное меню слева.

Манифест и JS входят в wheel, поэтому сохраняются и после установки пакета.
Весь Python-код работает в процессе ядра. Плагин не запускает свой сервер.

## Интерфейс

Доска и список, создание, редактирование и удаление с подтверждением,
перетаскивание между статусами, поиск и фильтры. На телефоне по умолчанию список.
Пока это деморежим: задачи хранятся в `localStorage` отдельно для каждого
пользователя, без записи в БД и синхронизации между устройствами.
При первом открытии показаны шесть примеров; пометка «Демо» видна в интерфейсе.
Исполнителем можно выбрать себя или оставить задачу неназначенной.
`store.js` заменим HTTP-клиентом после появления API задач.

## БД

Общая БД и фабрика сессий ядра; собственные метаданные и таблица `todo_tasks`.
Поля: UUIDv7, название, описание, статус, автор, необязательный исполнитель,
даты создания и изменения. Статусы: `new`, `in_progress`, `done`.
Удаление исполнителя снимает назначение; удалить автора существующей задачи нельзя.
Права редактирования реализуем в сервисе, таблица их не определяет.

Сначала применить миграции ядра, затем из корня workspace:

```powershell
uv run --all-packages python -m shtab_todo.migrate upgrade head
```

URL берётся из `SHTAB_DATABASE_URL`, как у ядра. История Todo хранится в
`alembic_version_todo`; `downgrade base` удаляет только таблицы плагина.
Миграции запускаются явно, не при каждом HTTP-запросе и не при `register(app)`.
`updated_at` обновляется SQLAlchemy при изменении модели; триггера для сырого SQL нет.

Пакет и интерфейс уже подключаются: `POST /api/plugins` с содержимым

workspace и сохраняет запись. После перезапуска ядро восстанавливает backend из БД.
